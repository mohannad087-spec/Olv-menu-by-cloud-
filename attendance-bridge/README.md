# جسر البصمة (attendance-bridge)

برنامج صغير يعمل على نفس الجهاز يلي شغّال عليه جسر الطباعة
([print-bridge](../print-bridge)) داخل شبكة المطعم، مهمته الوحيدة مراقبة
جهاز بصمة (بروتوكول ZK) وسحب سجل الحضور منه، وحفظه في نظام محاسبة OLV
تلقائيًا، بدون أي تدخل يدوي يومي.

## أي جهاز بصمة أشتري؟

أي جهاز حضور وانصراف بالبصمة يدعم **بروتوكول ZK** (وهو المعيار الشائع
عند أجهزة ZKTeco وأغلب الأجهزة المتوافقة/المقلّدة الرخيصة المنتشرة
بالأسواق) يشتغل مع هذا البرنامج، بشرط واحد مهم:

- **يجب أن يكون فيه منفذ شبكة (Ethernet) أو دعم واي فاي**، وليس فقط USB
  — لأن البرنامج يتصل فيه عبر الشبكة (المنفذ الافتراضي 4370)، تمامًا
  متل طابعة الشبكة.

لا تشتري جهاز بصمة USB-only (يحتاج توصيل مباشر بكمبيوتر واحد بالسلك
فقط) — دوّر تحديدًا على مواصفة "TCP/IP" أو "Network" أو "Ethernet" في
وصف المنتج.

## لماذا نحتاج هذا البرنامج؟

نفس سبب جسر الطباعة بالضبط: النظام هو موقع ويب عادي يعمل من أي متصفح،
والمتصفح لا يستطيع الاتصال مباشرة بجهاز على الشبكة المحلية. لذلك نحتاج
جهاز كمبيوتر واحد يبقى مفتوحًا ومتصلًا بنفس شبكة المطعم (يمكن أن يكون
**نفس الجهاز** الذي يشغّل جسر الطباعة، لا حاجة لجهاز إضافي)، ويتولى هو
سحب سجل البصمة نيابة عن النظام.

## خطوات التركيب (مرة واحدة فقط)

### 1. تركيب Node.js

إذا كان جسر الطباعة مركّبًا على نفس الجهاز، فـNode.js موجود مسبقًا
ويمكن تخطي هذه الخطوة. إن لم يكن، نزّل وثبّت Node.js (النسخة 18 أو
أحدث) من الموقع الرسمي: https://nodejs.org (اختر نسخة LTS).

### 2. نسخ هذا المجلد

انسخ مجلد `attendance-bridge` بالكامل إلى نفس الجهاز (بجانب مجلد
`print-bridge` إن وُجد).

### 3. تركيب المكتبات المطلوبة

افتح "موجه الأوامر" (Command Prompt / Terminal) داخل مجلد
`attendance-bridge` ونفّذ:

```
npm install
```

### 4. ضبط بيانات الاتصال بـ Supabase

انسخ ملف `.env.example` وأعد تسميته إلى `.env`، ثم افتحه بأي محرر نصوص
واملأ:

- `SUPABASE_URL` و `SUPABASE_SERVICE_KEY`: نفس القيم المستخدمة بجسر
  الطباعة تمامًا (من Project Settings → API، مفتاح **service_role**).
  هذا المفتاح سري جدًا — لا ترفعه إلى GitHub ولا تشاركه مع أحد. الملف
  `.env` مستثنى تلقائيًا من Git.

### 5. معرفة عنوان IP لجهاز البصمة

بنفس طريقة معرفة عنوان IP لطابعة الشبكة: من شاشة الجهاز نفسه (قائمة
الإعدادات → الشبكة/TCP-IP)، أو من تطبيق إدارة الراوتر. عدّل `DEVICE_IP`
في ملف `.env` بهذا العنوان. المنفذ الافتراضي `4370` يناسب أغلب الأجهزة
ولا داعي لتغييره غالبًا.

### 6. ربط كل موظف برقمه على جهاز البصمة

كل موظف يُسجَّل بصمته على الجهاز نفسه (من شاشة الجهاز مباشرة، حسب دليل
الجهاز)، ويُعطى الجهاز رقمًا داخليًا له (مثلاً 1، 2، 3...). افتح صفحة
**الموظفين** في نظام المحاسبة، وأدخل نفس هذا الرقم في حقل **"رقم
الموظف على جهاز البصمة"** لكل موظف — بدون هذه الخطوة، لن يستطيع
البرنامج معرفة صاحب أي بصمة.

### 7. تشغيل البرنامج

```
npm start
```

اترك هذه النافذة مفتوحة — طالما هي تعمل، ستُحفظ كل بصمة جديدة تلقائيًا
في نظام المحاسبة خلال ثوانٍ.

## تشغيل البرنامج تلقائيًا دون تدخّل يومي (موصى به)

بنفس طريقة جسر الطباعة، استخدم `pm2`:

```
npm install -g pm2
pm2 start src/index.js --name olv-attendance-bridge
pm2 save
pm2 startup
```

إذا كان `pm2` مركّبًا مسبقًا لتشغيل جسر الطباعة، فقط أضف السطر الثاني
(`pm2 start ...`) ثم `pm2 save` من جديد — لا داعي لإعادة `pm2 startup`.

## متابعة الحضور

من صفحة **الحضور** الجديدة في النظام، تظهر ورديات كل موظف (دخول/خروج)
يوميًا، مع إمكانية إضافة أو تصحيح بصمة يدويًا (لصاحب المطعم أو المدير
فقط) في حال نسي أحد الموظفين البصم أو تعطّل الجهاز مؤقتًا.

## أسئلة شائعة

**كيف يعرف النظام إذا كانت البصمة "دخول" أو "خروج"؟**
أغلب أجهزة البصمة الرخيصة لا ترسل إشارة موثوقة تفرّق بين الاثنين، لذلك
لا يعتمد النظام على ذلك أصلًا: يُحفظ كل بصمة كوقت مجرّد، والترتيب
الزمني لبصمات نفس الموظف بنفس اليوم هو من يحدد الدخول والخروج (الأولى
دخول، الثانية خروج، الثالثة دخول تاني... وهكذا). لو نسي موظف يبصم
خروجه، تبقى الوردية "مفتوحة" حتى تصحيحها يدويًا من صفحة الحضور.

**هل يمتلئ سجل الجهاز نفسه بمرور الوقت؟**
نعم، كل جهاز بصمة له سعة تخزين داخلية محدودة (عادة عدة آلاف من
السجلات). البرنامج لا يمسح سجل الجهاز تلقائيًا أبدًا (تفاديًا لفقدان
بيانات قبل التأكد من حفظها بأمان بالسحابة). إذا اقترب الجهاز من سعته
القصوى (راجع دليل الجهاز لمعرفة كيفية الاطلاع على نسبة الامتلاء)، يمكن
مسح السجل يدويًا من شاشة الجهاز نفسه بعد التأكد أن كل البصمات القديمة
محفوظة في صفحة الحضور بالنظام.

**هل يجب أن يكون هذا الجهاز مفتوحًا طوال الوقت؟**
نعم، طالما تريد تسجيل الحضور التلقائي أن يعمل. إن أُغلق الجهاز أو
انقطع عن الشبكة، تبقى البصمات محفوظة داخل جهاز البصمة نفسه وتُسحب
تلقائيًا فور إعادة تشغيل البرنامج والاتصال بالشبكة من جديد — لا تُفقد
أي بصمة.
