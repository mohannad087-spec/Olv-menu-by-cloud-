# محاسبة OLV — نظام محاسبي سحابي للمطعم

نظام محاسبة بسيط شغّال بالكامل من المتصفح (بدون سيرفر خاص بيك)، متصل بقاعدة
بيانات سحابية حقيقية على [Supabase](https://supabase.com) (مجاني للمشاريع
الصغيرة)، ومنشور تلقائيًا عن طريق GitHub Pages بتاعت الريبو ده.

## الميزات

- تسجيل دخول آمن للموظفين (Supabase Auth)
- **المبيعات**: تسجيل مبيعات كل يوم (كاش / شبكة / توصيل)
- **المصروفات**: تسجيل المصروفات وتصنيفها (مشتريات، رواتب، إيجار...)
- **الخزينة**: تقفيل يومي للكاش ومقارنة المتوقع بالفعلي
- **التقارير**: أرباح وخسائر لأي فترة، وتوزيع المصروفات حسب التصنيف
- كل البيانات محفوظة على السحابة ومتاحة من أي جهاز/متصفح

## خطوات التشغيل (مرة واحدة)

1. **أنشئ مشروع Supabase مجاني**
   - روح على https://supabase.com وسجّل واعمل New Project.
   - سيب المشروع يخلص التجهيز (دقيقة أو اتنين).

2. **جهّز قاعدة البيانات**
   - من لوحة تحكم Supabase: **SQL Editor → New query**.
   - افتح ملف [`schema.sql`](./schema.sql) في هذا المجلد وانسخ محتواه بالكامل،
     الصقه في المحرر، واضغط **Run**.
   - ده هيعمل كل الجداول والصلاحيات (RLS) والتصنيفات الافتراضية.

3. **اربط الموقع بالمشروع**
   - من Supabase: **Project Settings → API**.
   - انسخ **Project URL** و **anon public key**.
   - افتح ملف [`config.js`](./config.js) وحط القيمتين مكان:
     - `YOUR_SUPABASE_PROJECT_URL`
     - `YOUR_SUPABASE_ANON_PUBLIC_KEY`
   - احفظ وارفع (commit + push) الملف على GitHub — الموقع هيتحدث تلقائيًا
     عن طريق الـ workflow الموجود بالفعل (`.github/workflows/static.yml`).

4. **اعمل حساب لصاحب المطعم (Owner) وللموظفين**
   - من Supabase: **Authentication → Users → Add user**.
   - حط الإيميل وكلمة سر لكل موظف/كاشير محتاج يدخل النظام.
   - أول ما أي حساب يتعمل، بيتحط تلقائيًا في جدول `profiles` بدور `staff`.
   - لو عايز تدي حد صلاحية "owner" أو "manager": من **Table Editor → profiles**
     عدّل عمود `role` للمستخدم يدويًا.

5. **افتح النظام**
   - `https://<اسم-المستخدم>.github.io/<اسم-الريبو>/accounting/login.html`
   - سجّل دخول بأي حساب عملته في الخطوة 4.

## ملاحظات أمان

- مفتاح `anon key` مصمم يكون ظاهر في المتصفح — الحماية الحقيقية جاية من
  سياسات RLS في `schema.sql` اللي بتشترط تسجيل الدخول لأي عملية قراءة/كتابة.
- لو عايز تفصل بين صلاحيات owner/manager/staff بشكل أدق (مثلاً بس المدير
  يقدر يمسح قيود)، عدّل سياسات RLS في `schema.sql` على أساس عمود `role`.
- الريبو ده لازم يفضل **private** لو مش عايز أي حد يشوف كود الموقع، رغم إن
  بيانات المحاسبة نفسها محمية بتسجيل الدخول بغض النظر عن ده.

## هيكل الملفات

```
accounting/
  login.html          صفحة تسجيل الدخول
  index.html           لوحة التحكم الرئيسية (ملخص اليوم)
  sales.html           تسجيل وعرض المبيعات
  expenses.html        تسجيل وعرض المصروفات
  cash-register.html   تقفيل الخزينة اليومي
  reports.html         تقارير الأرباح والخسائر
  settings.html        إدارة تصنيفات المصروفات
  schema.sql           كود إنشاء قاعدة البيانات (يتشغل مرة واحدة)
  config.js            بيانات الاتصال بمشروع Supabase بتاعك
  assets/              التصميم (theme.css) والأكواد المشتركة (JS)
```

## تطوير مستقبلي (اختياري)

- إدارة المخزون (مواد خام، تنبيه نقص مخزون)
- ربط الأدوار (owner/manager/staff) بصلاحيات أدق داخل الواجهة نفسها
- تصدير التقارير كـ PDF/Excel
- دعم أكثر من فرع للمطعم
