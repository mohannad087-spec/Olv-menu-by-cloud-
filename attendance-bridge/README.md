# جسر الحضور (attendance-bridge) — أجهزة Hikvision

برنامج صغير يعمل على نفس الجهاز يلي شغّال عليه جسر الطباعة
([print-bridge](../print-bridge)) داخل شبكة المطعم، مهمته الوحيدة مراقبة
جهاز حضور Hikvision (مثل سلسلة MinMoe للتعرف على الوجه) وسحب سجل التحقق
منه، وحفظه في نظام محاسبة OLV تلقائيًا، بدون أي تدخل يدوي يومي.

هذا البرنامج مبني خصيصًا لأجهزة **Hikvision** (بروتوكول ISAPI عبر
الشبكة). لو عندك جهاز بصمة من ماركة تانية (ZKTeco أو مقلّد رخيص ببروتوكول
"ZK")، هذا البرنامج ما رح يشتغل معه — راجع الإصدار القديم بتاريخ git لو
احتجته.

## لماذا نحتاج هذا البرنامج؟

نفس سبب جسر الطباعة بالضبط: النظام هو موقع ويب عادي يعمل من أي متصفح،
والمتصفح لا يستطيع الاتصال مباشرة بجهاز على الشبكة المحلية. لذلك نحتاج
جهاز كمبيوتر واحد يبقى مفتوحًا ومتصلًا بنفس شبكة المطعم (يمكن أن يكون
**نفس الجهاز** الذي يشغّل جسر الطباعة، لا حاجة لجهاز إضافي)، ويتولى هو
سحب سجل التحقق نيابة عن النظام.

## خطوات التركيب (مرة واحدة فقط)

### 1. تفعيل الجهاز وضبط شبكته (مرة واحدة من الجهاز نفسه)

أجهزة Hikvision تتطلب "تفعيل" إجباري أول مرة (تضبط فيه كلمة سر المدير)
قبل أي استخدام:

- شغّل الجهاز ووصّله بنفس شبكة الواي فاي/الشبكة السلكية للمطعم (من
  شاشة الجهاز نفسه → الإعدادات → الشبكة).
- اتبع خطوات "Activation" على شاشة الجهاز، واختر كلمة سر مدير **قوية
  ومختلفة** (هاي هي القيمة اللي رح تحطها بـ`DEVICE_PASSWORD` بالخطوة 4).
- من شاشة الجهاز → الإعدادات → الشبكة، لاحظ عنوان **IP** الحالي (رح
  تحتاجه بالخطوة 4). بديل: نزّل أداة **SADP Tool** المجانية من موقع
  Hikvision على أي كمبيوتر بنفس الشبكة — بتكتشف الجهاز وتوريك IP تلقائيًا.

### 2. تسجيل وجوه الموظفين على الجهاز

من شاشة الجهاز نفسه (أو برنامج iVMS-4200 لو متوفر)، أضف كل موظف: اسمه،
صورة وجهه (أو بصمته لو الجهاز يدعم ذلك)، ويُعطى الجهاز رقمًا داخليًا له
("Employee No.") — هذا الرقم هو اللي رح تربطه بصفحة الموظفين بالخطوة 6.

### 3. تركيب Node.js ونسخ المجلد

إذا كان جسر الطباعة مركّبًا على نفس الجهاز، فNode.js موجود مسبقًا
ويمكن تخطي هذه الخطوة. إن لم يكن، نزّل وثبّت Node.js (النسخة 18 أو
أحدث) من الموقع الرسمي: https://nodejs.org (اختر نسخة LTS).

انسخ مجلد `attendance-bridge` بالكامل إلى نفس الجهاز (بجانب مجلد
`print-bridge` إن وُجد)، وافتح "موجه الأوامر" داخله ونفّذ:

```
npm install
```

### 4. ضبط ملف الإعدادات

انسخ ملف `.env.example` وأعد تسميته إلى `.env`، ثم افتحه بأي محرر نصوص
واملأ:

- `SUPABASE_URL` و `SUPABASE_SERVICE_KEY`: نفس القيم المستخدمة بجسر
  الطباعة تمامًا (مفتاح **service_role**، سري جدًا — لا تشاركه). الملف
  `.env` مستثنى تلقائيًا من Git.
- `DEVICE_IP`: عنوان IP الجهاز (من الخطوة 1).
- `DEVICE_USER` و `DEVICE_PASSWORD`: بيانات دخول المدير اللي ضبطتها وقت
  التفعيل (الخطوة 1).

### 5. اختبار الاتصال بالجهاز (مهم — قبل أي شي تاني)

نفّذ من داخل مجلد `attendance-bridge`:

```
npm run test-connection
```

لو ظهرت علامة ✓ بالخطوتين، الاتصال شغّال والبرنامج جاهز. لو ظهر خطأ،
الرسالة بتوضحلك السبب الأرجح (شبكة، IP غلط، كلمة سر غلط...).

### 6. ربط كل موظف برقمه على الجهاز

افتح صفحة **الموظفين** في نظام المحاسبة، وأدخل نفس رقم "Employee No."
(من الخطوة 2) في حقل **"رقم الموظف على جهاز البصمة"** لكل موظف — بدون
هذه الخطوة، لن يستطيع البرنامج معرفة صاحب أي بصمة (`npm run
test-connection` بيوريك هالأرقام كمان بآخر أحداث الجهاز).

### 7. تشغيل البرنامج

```
npm start
```

اترك هذه النافذة مفتوحة — طالما هي تعمل، ستُحفظ كل بصمة جديدة تلقائيًا
في نظام المحاسبة خلال ثوانٍ.

## تشغيل البرنامج تلقائيًا دون تدخّل يومي (موصى به)

بنفس طريقة جسر الطباعة، استخدم `pm2`:

```
npm install -g pm2
pm2 start src/index.js --name olv-attendance-bridge
pm2 save
pm2 startup
```

إذا كان `pm2` مركّبًا مسبقًا لتشغيل جسر الطباعة، فقط أضف السطر الثاني
(`pm2 start ...`) ثم `pm2 save` من جديد — لا داعي لإعادة `pm2 startup`.

## متابعة الحضور

من صفحة **الحضور** في النظام، تظهر ورديات كل موظف (دخول/خروج) يوميًا،
مع إمكانية إضافة أو تصحيح بصمة يدويًا (لصاحب المطعم أو المدير فقط) في
حال نسي أحد الموظفين البصم أو تعطّل الجهاز مؤقتًا.

## أسئلة شائعة

**كيف يعرف النظام إذا كانت البصمة "دخول" أو "خروج"؟**
البرنامج ما بيعتمد على أي إعداد "دخول/خروج" بالجهاز نفسه — يكفي إنك
تبصم وبس (وجهك أو بصمتك حسب الجهاز)، وترتيب بصماتك الزمني باليوم هو
يلي بيحدد تلقائيًا الدخول والخروج بنظام المحاسبة (الأولى دخول، الثانية
خروج، الثالثة دخول تاني...). لو نسيت تبصم خروجك، تبقى الوردية "مفتوحة"
حتى تصحيحها يدويًا من صفحة الحضور.

**هل يجب أن يكون هذا الجهاز (الكمبيوتر) مفتوحًا طوال الوقت؟**
نعم، طالما تريد تسجيل الحضور التلقائي أن يعمل. إن أُغلق الكمبيوتر أو
انقطع عن الشبكة، تبقى البصمات محفوظة داخل جهاز Hikvision نفسه وتُسحب
تلقائيًا فور إعادة تشغيل البرنامج (البرنامج يسحب نافذة تصل لـ72 ساعة
للخلف بكل مرة تلقائيًا — راجع `LOOKBACK_HOURS` بملف `.env` لو احتجت
مدة أطول بعد انقطاع أطول).

**البرنامج بيطلع تحذير "رقم موظف غير مربوط" — شو أعمل؟**
معناها في بصمة وصلت من رقم "Employee No." مش موجود بعمود "رقم الموظف
على جهاز البصمة" لأي موظف بصفحة الموظفين — تأكد إنك كتبت نفس الرقم
بالضبط (بدون مسافات إضافية).

**هل جرّبتوا هذا البرنامج فعليًا على جهاز Hikvision حقيقي؟**
منطق المصادقة (Digest Auth) وترقيم صفحات النتائج اختُبرا بمحاكاة دقيقة
لسلوك الجهاز المتوقع حسب توثيق Hikvision الرسمي (ISAPI)، لكن **لم
يُختبرا بعد على جهازك الفعلي** لأنه غير متاح وقت كتابة البرنامج. لهذا
خطوة `npm run test-connection` (الخطوة 5) مهمة جدًا — بتطبع الرد الخام
الكامل من جهازك، فلو كان شكله مختلف عمّا هو متوقع، ابعت الناتج حتى
تُصحَّح البرمجة على أساسه.
